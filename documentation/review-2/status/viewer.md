## Decisions

- Giant lines: at most 262,144 checkpoints per 4 MB segment (3 MB); a lookup in a line of 50 GB decodes about 200 KB.
  The distance rule (average 4 KB) still applies below that.
- Short read inside a file's length = the file changed: it ends the scan/walk, keeps what was found and sets a read
  error ("The file changed while it was being read…") shown in the status line.
- Files that do not report a size and cannot be statted (servers) are read to measure only up to 1 TiB and with a cancel
  check each megabyte.
- Special files (pipes, devices, sockets, also behind links) are refused, not opened.
- Page mode / RTF: HTML over 8 MB and RTF over 4 MB fall back to the text modes. Copies of remote media for the players:
  refused above 1 GiB or when less than 256 MB would be left; idle copies at most 2 and 512 MB.
- Links in a viewed page: relative links inside the folder of the shown file (and below) are followed in the viewer;
  http/https/mailto after a click in the default program; everything else is ignored. Same rule for RTF/PDF (web/mail
  only).
- Copy to the clipboard: 16 MB text, 8 MB hex. Print: first 512 KB.
- Image files with several images that are not an animation show the largest; images claiming more than 400 megapixels
  are not decoded.
- Case-insensitive text search compares characters folded as `String.folding(.caseInsensitive)` does (ß = ss, ligatures,
  Kelvin sign), whole characters only; control characters are never skipped.
- Cleanup queue work (closing readers, deleting copies) is concurrent and `userInitiated`; `TemporaryCopies.removeAll`
  waits at most 2 s (plugin stop).

## Tests

New: `Tests/PluginTests/Review2ViewerRowsTests.swift`, `Review2ViewerSearchTests.swift`,
`Review2ViewerSourceTests.swift` (with `Review2HookProvider`), `Review2ViewerPaneTests.swift`. Updated for deliberate
behaviour changes: `ViewerFixTests` (temporary copies are deleted in the background: `waitForCleanup()`),
`ViewerAdoptPaneTests` (`ViewerCleanup.drain()`), `ViewerAdoptRichTests` (links: no `data-href` decoy, no `href` inside
a title), `ViewerAdoptHTMLReference.swift`.

The `PluginTests` target did not build in the project tree at the end because of other areas' files
(`NetworkPluginTests.swift`: `boundAccount` is internal), so the Viewer tests were built and run in an isolated copy of
the tree: the sources and tests of the state before the round (`build/backups/before-round2-fixes.tgz`) with the viewer
area's files copied over. The viewer module also builds on its own in the project tree against the current kernel
(`swift build --scratch-path .build-viewer --target ViewerPlugin`).

Result of the final run (`swift test --filter Viewer` in the isolated tree): 146 tests in 15 suites passed (50 s), 0
failures. That is the 109 tests that existed plus the 37 new ones in the four `Review2Viewer*` files.

## Not done

- V035: East Asian wide characters still take one column (a width of 2 would need the fast paths that cut short lines
  unseen to know about it); only combining marks and joiners were done.
- V069: a sequential (remote) scan still reads a giant line twice; V024: the number of index builds/loads in flight is
  not capped (a stuck read on a share that cannot be interrupted still holds one thread); V079: same, for loads.
- V021/V039/V056: the PDF link delegate (`pdfViewWillClick(onLink:with:)`) and the RTF `clickedOnLink` return value were
  not run in a window; the pure rules (`LinkPolicy`) and the web view decision are tested. I rely on PDFKit not opening
  the URL itself when the delegate method exists.
- V070, V038: the parts in FileProperties/FileTools (see `cross-requests/viewer.md`).
- V034: no test for the pixel limit.
- A FIFO that replaces a regular file between the `stat` and the `open` would still block that one load thread (the
  local provider's reader opens by path; `LocalFileSystem` is not mine).
