## 2. Decisions

1. **A server nobody chose is asked about.** A location on a server that is neither a saved connection nor one the user
   opened in a dialog of the plugin leads to "Connect to X?" before the first login. This also happens once for an
   address typed into the command line, because typed text and text from a tab file reach the plugin the same way
   (cross-request 4).
2. **Passwords are bound to the server and login.** They are kept under identifier + scheme + host + port + user.
   Passwords an earlier version kept under the identifier alone are moved once, the first time the new version sees the
   saved connections; a marker in the Keychain prevents a second move.
3. **Trusted certificates left the settings.** They are kept in the Keychain. What an earlier version kept in
   `network.trustedCertificates` is ignored and emptied, so each such server asks once more.
4. **A changed certificate needs a ticked box**, not only a button, and the new fingerprint replaces the old ones. There
   is no "this once" for a changed certificate.
5. **Plain FTP with a password asks first**, once per server, with "Do not ask again for this server". Servers on this
   machine (`localhost`, `127.*`, `::1`) are not asked about.
6. **A password question that names nobody is not answered with the stored password.** The user is asked.
7. **Download lists.** A plain line may only download from a server to this Mac; anything else must start with `put:`,
   `copy:` or `move:`. Limits: 4 MB per list file, 100 000 lines, 60 s per `sleep:`. A name with a line break is
   refused, not escaped (the file format has no escape). When the target name exists the choice is "Replace" or "Keep
   Both" (the new file keeps the name it arrived with).
8. **Limits for what a server sends.** Line 4096 bytes; reply 1000 lines/64 KB kept, 20 000 lines read, one timeout for
   the whole reply; listing 4 000 000 entries and 1 GB; SFTP packet 1 MB. A size too large for a number is the largest
   number; a size below zero or not a number is 0; a date outside the years 1…9999 is no date.
9. **Waits.** A wait for a connection, a transfer slot or another thread's login ends when nothing moved on the session
   for 60 s (or twice the timeout, whichever is longer). The time a question to the user is open does not count. The
   main thread never waits for a login lock.
10. **Logins per server (N077).** The limits are unchanged (up to 3 for commands and 4 each for downloads and uploads at
    the default setting). A shared lower cap would make a listing wait for a running transfer. Instead a 421 makes the
    thread wait for a connection that comes free.
11. **Closing a reader returns at once.** The server is told in the background. A thread that needs a connection waits
    up to 0.5 s for one that is on its way back before it logs in again.
12. **A name that cannot be told apart from the slash next to it** (it begins with a combining mark, or ends with a
    character that joins what follows) is left out of listings and refused in paths.
13. **FTPS servers that insist on TLS session reuse** stay unsupported; the clear error is kept. `Network.framework`
    gives no way to resume the control connection's session on a data connection.
14. **A notice of ssh that wants no answer** (touch the security key) goes to the connection log; there is no window for
    it.
15. **`ServerKey.url` for a host that has no URL** gives a location on `host.invalid`, never on the local disk.
    `ServerAddress` refuses such hosts, so this is only reached by a key made by hand.

## 4. Not done

- **Built but not tested**, because the tests cannot reach the real thing: the Keychain update order (N100), cancelling
  and timing out a system mount (N066, N103), the certificate check on its own queue (N057), the window on a really slow
  line (N039). The code compiles and was read through.
- **Left to other areas** (see `cross-requests/network.md`): putting the download mark on local copies (N009: the
  provider returns it, the copying side must apply it), a cancellation flag for the four changing provider calls
  (N010/N026: their waits are bounded, not cancellable from the progress window), a dialog with a safe default button,
  and a way to tell a typed address from one read from a file.
- **Known limits that remain:** an FTP server with neither SIZE nor MLST cannot have its uploads measured (N029); an FTP
  server without MLST is still believed for up to 10 s that a name is free when no alike name is listed (N034); a name
  that is not valid text in the encoding forced for an FTP connection cannot be addressed (N022); FTPS with required TLS
  session reuse is not supported (decision 13).
- **A deadlock in the test harness, not in the program:** a question asked while `FakePanel` reads a folder on the main
  thread cannot be answered, because the kernel now lists on its own thread while the fake waits on the main thread. The
  test for a typed address therefore answers the "Connect?" question without the dialog, and the dialog is tested by
  itself. The real panels do not read on the main thread.
- The fuzzers were not run again (the fuzz package builds every plugin); the three reproducers are tests.
