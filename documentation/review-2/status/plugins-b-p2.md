## Decisions

- Wide characters: only classes W and F are two columns; ambiguous (A) is narrow. A combining mark or joiner adds
  nothing; a cut in front of one is never made.
- Index builds: 2-4 at a time by cores, 8 stuck threads at most; the sixth refusal message is a read error shown in the
  status line, not a dialog.
- A load that is given up leaves its question running on a kernel thread (bounded by `BlockingCalls.limit`, 64 per file
  system); its result is dropped and the source it made is closed by its `deinit`.
- Print limit 2,000 pages (about 130,000 lines at 66 lines a page); beyond it the message says so before the print
  panel. Rows wider than the page are shrunk to fit by the print operation (`.fit`).
- JIS X 0212 characters in EUC-JP show as U+FFFD (one per character), because the system's EUC-JP converter has none.
- BLAKE3 spreads over the cores only while fewer files than cores are being hashed.
- Selections of 20,000 marks or more are read in the background for Synchronize directories, and the window's "Only
  selected files" box becomes available when they have arrived.

## Tests

Added `Review2PluginsBP2ViewerTests.swift` (suite `Review2PluginsBP2Viewer`) and `Review2PluginsBP2ToolsTests.swift`
(suite `Review2PluginsBP2Tools`). Changed: `Review2ViewerPaneTests.swift`, `ViewerAdoptRichTests.swift` (the image tests
above). Changed besides: `Review2ViewerSourceTests.swift` (EUC-JP and GB 18030 are offered again),
`CompareContentDiffTests.swift` (the 60 s bound of the heuristic diff is the thread's processor time, not the clock).

Final runs (machine at a load average above 100):

- `--filter "Viewer|FileTools|CompareContent|DirectorySync|SyncTools|ToolsAdopt|Review2Viewer|Review2Tools|Review2PluginsBP2|Review2FileTools|Review2DirectorySync|Review2Compare|MyersDiff"`:
  412 tests in 47 suites, 0 failures (twice, the second after the last change).
- Wide run `--filter PluginTests --skip Network` (before the last two test-only changes): 1,541 tests in 190 suites, 4
  issues. Two are other areas' (`Review2LocalfsTests.thePlacesAreAnsweredAndAnnouncedWhenTheyChange`,
  `Review2KernelP2LocalTests.aTreeIsWatchedAsOneAndAFolderOnlyForItself`). Two were mine, both of the kind "waited 30 s
  for the main actor while other tests held it": `aFrameIsScaledOnceForTheSizeItIsShownAt` (its wait is now 300 s; the
  cache queue is held still in the image tests, so no count depends on timing) and, in the run before,
  `aCancelledCompareOverEditedContent…` (wait 240 s). A first run of the viewer filter also showed two real failures
  that were fixed: a zero-width unit cut a surrogate pair in two in a row of one column, and `segmentsReused` no longer
  counted a trailing empty segment.

## Not done

- The PDF click: it is not known without a window whether PDFKit opens a link itself when the delegate method exists;
  the gate relies on the delegate method being the whole handling.
- A provider that ignores `interrupt` and a read that never returns are only bounded (the gate, `BlockingCalls`), not
  ended; there is no test with such a provider.
- The quarantine mark is not carried by Split/Combine/Encode/Decode from a remote source (they write new data, not
  copies); only the viewer's copies and Sync's streamed copies carry it.
- FileProperties parts of V070/T024/T047: see `cross-requests/plugins-b-p2.md` 1.
