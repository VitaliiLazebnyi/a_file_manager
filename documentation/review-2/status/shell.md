# Review 2 — status of the shell area

Fix agent: shell (`Sources/AFMShell`, `Sources/AFileManager`, `Sources/StandardPlugins`, `Tests/ShellTests`). Paths
below are relative to `Sources/AFMShell` unless they say otherwise.

The mechanisms most rows refer to:

- **`Background`** (`App/Background.swift`): the shell's own threads. `Background.storage(purpose, at: location)` runs a
  call that may wait on a file system in the lane of that purpose and location: one call at a time per lane, each lane
  on a thread of its own, nothing on `DispatchQueue.global`. A location that does not answer holds up its own lane only,
  and a second call for it never starts before the first has returned. `Background.compute` is a small pool for sorting,
  filtering and searching; `Background.release` frees large lists off the main thread.
- **`MainLoop`** (same file): results come back to the main thread through the run loop (`CFRunLoopPerformBlock`, common
  modes), not through the main dispatch queue, so a completion may show a dialog without stalling everything else.
  `MainLoop.dialog` shows one dialog after the other. `MainOwned` makes closures that hold panels be released on the
  main thread.
- **Quiet re-reading** (`Panel/PanelViewController.swift`): at least `max(0.5 s, 2 × cost of the last reading)` between
  the end of a reading and the next quiet one, any number of reports in between collapsing into one; the location is
  announced only when it differs from the one announced last.

## 2. Decisions

1. Quiet re-reads wait `max(0.5 s, 2 × the last reading's time)` after any reading of the tab, quiet or not.
2. A job that has not stopped 10 s after Cancel: the user is asked "Stop Waiting" / "Keep Waiting" (again after 20 s, 40
   s, …). A job that is left behind keeps its thread; its completion still runs when it returns. Commands are unblocked
   meanwhile, although that job may still touch files when the system lets it go.
3. Quit with a job that does not stop: after 5 s "Quit Anyway" / "Keep Waiting" (doubling). Quit Anyway may leave a
   half-written file.
4. Drags of up to 2,000 items still write one pasteboard item per local file (what other programs expect); larger drags
   write one item plus a lazily built list of paths (`NSFilenamesPboardType`), which some programs may read as one file.
5. A drop with an `afm.panel-item` type from another program is treated as a drop of its local file URLs only.
6. A folder that delivers nothing is entered empty after 0.25 s (was 0.1 s).
7. The location is announced when the first entries or a remembered listing are shown, not only at the end of the
   reading; the start-up folder is announced only if the panel ends up somewhere else (as before).
8. Read-ahead: 60 s pause for a listing the cache did not keep, 1 h for a folder over the cache's entry limit; the QoS
   boost for a joined reading is a `pthread` override.
9. Control characters are shown as control pictures (U+2400…), direction controls and C1 controls as U+FFFD.
10. A failed non-quiet reload reports the error and leaves the list as it is, marked complete, rather than "loading" for
    ever.
11. The plugins' menus are enabled manually (`autoenablesItems = false`); an entry's state is brought up to date when
    its menu opens and when its key is pressed. The Help menu's search may show a stale state; running a command is
    still guarded by `CommandRegistry.perform`.
12. Own icons are never asked for files on non-local volumes, and appear a moment after the type icon elsewhere.
13. Only listed folders are watched; if setting a watch up took over 0.5 s the folder is re-read once.
14. Without a known change the bars are validated at most once a second while events arrive.
15. The drive bar and the volume list are empty until the file systems have answered `places()` in the background.

## 3. Tests

Added: `Tests/ShellTests/Review2ShellTests.swift` (28 tests: 16 in `extension Application`, 12 in suite
`Review2ShellParts`). Updated for deliberate changes: `RememberedListingTests.swift` (three tests wait for the pause
before a re-read / for the read-ahead to return), `PanelPartsTests.swift` (`draggedItemsTravelOnThePasteboard` uses the
drag ticket), `WindowTests.swift` (drive bar waits for the places).

Final run, `swift test --scratch-path .build-shell --filter ShellTests` from the project root, after the last source
change: the ShellTests target ran 154 tests in 8 suites, 0 failures. (The same filter also matches another area's suite
`PluginTests.Review2ConfigAShell`: 12 tests, passed.) While other areas' test targets did not compile, the ShellTests
target was run alone from a scratch package that links the same sources; those runs are what the intermediate results
came from.

One test was found sensitive to machine load and made robust (`aReloadThatIsTurnedAwayWhileTheFolderIsRead…`: its 0.4 s
listing delay could pass before the test got its next turn at a load average above 100).
