## 3. What was changed, file by file

### Kernel (`Sources/AFMKernel`, `Sources/AFMContracts`)

- `Panels/Sorting.swift` — `Sorter.compare(_:_:numeric:)`, `Sorter.sorted(_:numeric:byName:)`, `Sorter.key(of:numeric:)`
  (`NameKey`, comparable): the order of names for code outside the panels' lists, on the collation keys the sorter
  already uses, with a second collator for "digits by value". Needed because K001 (Foundation's localized comparison
  ends the program for certain names, and is no order) was fixed inside the sorter only; 21 call sites in plugins still
  used it. `Int32(clamping:)` for a name's length.
- `Support/Parallel.swift` — `ThreadTime.used`: the calling thread's processor time, for limits on work (failure 13).
- `Panels/PanelModel.swift` — `prepare(_:show:focus:history:complete:remembered:presorted:)`: entering a folder,
  prepared on any thread (sort, filter, index of names, totals) and applied with `apply` (shell-p2 request 2).
  `Prepared.deinit` lets go of the fresh listing it keeps off the main thread (shell-p2 request 1).
- `AFMContracts/Services.swift` — `Kernel.userTyped(location:proposal:relativeTo:)`: tells the `ServerConsentService`
  about text typed as a place; nothing for text without `scheme://`, nothing for a proposal left as it was.

### File operations

- `FileOperations/FileJob.swift` — everything below a folder the job walks into is removed with
  `remove(_:below:cancellation:)` from the job's own source folder down (delete; the originals of a move, at once or
  after a commit); the sources themselves by path (F043). The commit of a move is made with
  `commit(_:cancellation:progress:)`: a report goes out from inside the commit, which is where a paused job waits, and
  Cancel ends it (F046). Sorting by `Sorter.sorted`. (Exclusive `createDirectory` and the flagged `copy` were already in
  use.)
- `FileOperations/FileOperationsPlugin.swift` — the typed target of Copy/Move is reported (`userTyped`); "Rename each
  file separately" takes the marked items one by one instead of making the list of all of them first; New Folder / New
  Text File are withheld where entries can only be removed (`.removeOnly`).
- `Clipboard/ClipboardPlugin.swift` — Paste and "Save Details to File" withheld in a `.removeOnly` location.
- `FileProperties/FilePropertiesPlugin.swift` — Change Attributes, Properties (several items) and Create Link take
  `operandsSnapshot()` on the main thread and make the list on the job's thread.

### Archives

- `OpenArchive.swift`, `ArchiveFileSystem.swift` — `commit(_:cancellation:progress:)` implemented: asked before every
  member that is written and between the blocks of an upload, with bytes written and expected; false ends the write,
  which then has changed nothing. `copy(_:to:cancellation:progress:)` hands the flag to the file system outside the
  archive. The upload's final rename takes the flag. The reaper of parked readers runs from the plugin's own clock, not
  a shared queue.
- `Unpacker.swift` — by path (a target that is not a disk of this Mac): folders are made level by level; one that exists
  must be a real folder, one that does not is made with `createDirectory(at:exclusive:true,cancellation:)` (L043). The
  parallel unpacking runs on a kernel thread, not on the shared pool. The flag goes to the remaining changing calls; the
  read loops drain an autorelease pool per block.
- `Packer.swift` — the job's flag for `createDirectory`, the final `move`, and the removal of sources after "Move to
  archive". `ArchivesPlugin.swift` — the sweep of leftovers on a kernel thread. `ArchiveCommands.swift` — typed pack and
  unpack targets reported.
- `ByteStreams.swift` — `OutputFile(extending:)` opens without waiting, through no link, and refuses what is not a
  regular file.
- `root(of:)` (K039) was already implemented by the archives agent; read and found equal to the climb, nothing changed.

  plain, 6 under the thread sanitizer, 4 under the address sanitizer). The product's own net is the empty handler
  `Kernel.init` installs; a test that writes to a broken pipe before any kernel exists in its process would still die.
- **Nothing was run in the real program**, and nothing against a real dead share, a real server or a real second mount.
  What the earlier agents wrote about that stands.
- **The sanitizers ran once each on the final sources** (TSan 6, ASan 4); the earlier runs were of trees that still
  changed. The tests that failed only under a sanitizer were each fixed and then passed in the later runs of that
  sanitizer (two or three each), not in many.

  s), once in ten sanitizer runs.
