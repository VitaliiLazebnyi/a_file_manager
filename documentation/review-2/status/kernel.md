## 2. New kernel API (all additive)

### Blocking work off the dispatch queues — `BlockingCalls` (`Support/BlockingCalls.swift`)

- `BlockingCalls.run { }`: runs work on a thread of the kernel's own (named `AFM.Blocking`, made on demand, kept 5 s
  when idle, inside an autorelease pool). For anything that may wait on something outside the program.
- `BlockingCalls.answer(from: provider, to: "volume " + key, sharing: true, cancellation: flag) { flag in … } -> Answer?`:
  asks on a kernel thread and waits on the calling thread (not the main thread). Equal questions to one owner are asked
  once; with `sharing: false` each asker gets its own answer, one after the other once an earlier one was given up. At
  most `BlockingCalls.limit` (64) per owner under way; further ones wait without a thread. Returns nil as soon as
  `cancellation` is set; the work is told through the flag it was handed.
- The same with `then:`: returns at once and delivers on the main thread (nil when cancelled first).
- `BlockingCalls.unanswered(for:)`: how many questions to an owner have not come back.
- `Discard.later(&array)` / `Discard.later(&optional)`: releases a long list on a kernel thread.

### Paths from outside — `PathSafety` (`FileSystem/FileItem.swift`)

Byte-based: `isSafeName(_:)` (not empty, not `.`/`..`, no `/` byte, no NUL),
`components(ofRelativePath: allowingTrailingSeparator:)` (cut at the `/` byte; nil unless every part is safe),
`location(ofRelativePath:below:)`, `isContained(_:in:resolvingLinks:)` (paths written out in full and compared byte by
byte; with links resolved also for a file that does not exist yet), and `URL.appending(safeName:) -> URL?`.
`URL.isInside` compares bytes now.

### Panel model (`Panels/PanelModel.swift`)

- `basis` (O(1), main thread) → `PanelModel.prepare(basis, sort:)`, `prepare(basis, filter:)`,
  `prepare(basis, update:focus:presorted:)`, `prepare(basis, extendingTo:sortedBy:)` (any thread) →
  `apply(prepared) -> Outcome` (`.stale` / `.unchanged` / `.changed`; main thread). Marks, the cursor and calculated
  sizes that change in between are kept; a change of the list, the filter or the order makes the result stale.
- `listVersion` moves only with `listedItems`; `shownVersion` moves with list, filter and order (guard for indexes of
  `items`).
- Marks: `hasSelection`, `selectedNames`, `select(where:select:)`, `PanelModel.rows(of:where:)` + `setSelection(_:_:)`,
  `setSelected(_:indices:shownVersion:)`, `setSelection(indices:shownVersion:)`, `operandsSnapshot()` (`items()`,
  `markedItems()`, `markedIndices()`, `isMarked(at:)` on any thread).
- `setSort(_:presorted:listVersion:) -> Bool`; `Snapshot.filter`, `Snapshot.sort`.

### Other

- `Parallel.isHoldingUpMainThread`, `Parallel.assertMayWaitForMainThread()`.
- `FileSystemProvider.volume(of:cancellation:)`; `TreeWalk.nesting`.
- `Int64.subtractingSaturated`, `multipliedSaturated(by:)`, `Int64(saturating:)`, `Int.addingSaturated`,
  `Int.multipliedSaturated(by:)`.
- `Kernel.init` installs an empty handler for `SIGPIPE` (unless one is installed): a write to a broken pipe is `EPIPE`
  in this program, and programs it starts keep the system's default.

## 4. Decisions

- **The order of names is the collator's, not the localized comparison's.** Names are ordered by ICU sort key at
  secondary strength (letters and accents count, case does not, punctuation is not ignored), then by their UTF-8 bytes.
  Lists can come out in a slightly different order than before where the old comparison was inconsistent, and names that
  differ only in case or in how an accent is written are now in byte order. Without the system's collator the key is the
  lowercase form.
- **A mark belongs to one entry.** Two entries of the very same name (a list gathered from several folders) can be
  marked one without the other; marking by _name_ marks every entry written like it. `selectionCount` counts entries.
- **`listVersion` no longer moves with a filter, a calculated size or a no-op refresh.** Whoever guarded indexes of
  `items` with it uses `shownVersion`.
- **`restore(snapshot)` keeps the panel's present order** and re-sorts the restored list if the order changed since the
  snapshot (rare; on the calling thread). The filter is the snapshot's.
- **File masks:** `[` `]` `\` are ordinary characters; `?` is one Unicode scalar; matching ignores case by full case
  folding and the way accents are written.
- **Limits:** 64 unanswered questions per file system (`BlockingCalls.limit`); a size walk nests 32 calls per thread and
  gives up 1000 levels below that; a tree of pool jobs gets `width` threads, up to 4 x `width` when its pieces wait and
  finish; the pool never has more than max(64, 16 x `width`) threads; root answers are remembered 30 s.
- **A listing waits behind a given-up listing of the same location** instead of starting a second one; two live listings
  of one location (two panels) still run side by side.
- **`PanelLoader.stream` called on the main thread** (tests, small tools) asks the file system directly, as before.
- **`SIGPIPE`** is caught by an empty handler, not ignored: "ignored" is inherited by programs started with a plain
  `posix_spawn` (measured: such a child survives `kill -PIPE` under `SIG_IGN` and ends as usual under the handler;
  Foundation's `Process` resets it either way), so `ssh` and the user's shell commands keep the default.
- **`Format.kilobytes`** rounds negative numbers to the nearest too (it truncated toward zero before).
- **`duplicate()`** of a tab that is still loading is not complete either, until the shell reads it.
