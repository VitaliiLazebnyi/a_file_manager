# Appendix A: Host differences (Wine/CrossOver vs Windows)

Most of this specification was first observed under CrossOver (Wine) on macOS and then checked on a Windows 11 virtual
machine. This appendix collects everything that depended on the host rather than on Total Commander: artefacts a clone
must not copy, values that depend on DPI and fonts (with both measurements), defaults that differed between the two
sessions together with the real default, and keys the host did not deliver. The topical chapters state the Windows 11
behaviour and refer here for the rest.

**Related:** [Appendix B](B-investigation-and-test-setup.md) (hosts, sandboxes and test setup), [02](02-main-window.md)
› Fonts, Icons, Window geometry and rendering metrics; [13](13-configuration-dialog.md) › Display › Font, Display ›
Icons, Display › Tabstops/Data Formats; [19](19-settings-files-and-command-line.md) › INI rules; [06](06-keyboard.md).

## 2. Values that depend on DPI and fonts

### 2.1 Display defaults

TC picks these defaults from the screen DPI and the available fonts. The topical chapters give the Windows 11 value with
"(depends on DPI/font; see Appendix A)".

| Setting (13 › Display › Font, Icons, Tabstops/Data Formats; ini key) | Wine, 96 DPI               | Windows 11, 200 % (192 DPI)                             |
| -------------------------------------------------------------------- | -------------------------- | ------------------------------------------------------- |
| Font › File list font (`Fontname`, `Fontsize`)                       | Microsoft Sans Serif,8,b   | **Segoe UI,9** (regular: neither Semibold nor bold)     |
| Font › Main window font                                              | Microsoft Sans Serif,8,b   | **Segoe UI,9**                                          |
| Font › Dialog box font                                               | Microsoft Sans Serif,8     | Microsoft Sans Serif,8                                  |
| Font › Set dots per inch (DPI) to (disabled by default)              | `[96]`                     | `[192]`                                                 |
| Icons › Icon size (`Iconsize32`)                                     | 16x16                      | **32x32**                                               |
| Tabstops › Extension / Size / Date/Time / Attributes / Comments (px) | 147 / 209 / 213 / 273 / 90 | **176 / 234 / 238 / 299 / 91**                          |
| Screen-resolution section of `wincmd.ini`                            | `[1728x1117 (8x16)]`       | `[3456x1896 (10x20)]`                                   |
| Button-bar icon caches                                               | not written                | `default.br2` 77,710 bytes, `vertical.br2` 25,906 bytes |

- The help names **Segoe UI Semibold, 9** as the font of a fresh installation (`UseNewDefFont=-1` → 1, Windows Vista and
  later) and Microsoft Sans Serif 8 bold as the fallback and the default of existing installations. Windows 11 showed
  Segoe UI 9 regular. Under Wine the fallback appeared although the ini held `UseNewDefFont=1`; whether the bottle
  lacked Segoe UI was not checked.
- The section name is `[<width>x<height> (<a>x<b>)]`. The pair in parentheses appears to be the system-font character
  cell: 8×16 at 96 DPI ("small fonts"), 10×20 at 120 DPI ("large fonts"); this is an interpretation, as the help does
  not explain the pair. At 192 DPI it was still 10×20. At 200 % the section carried the physical resolution (3456×1896),
  while the window geometry was measured against a logical screen of 1728 × 1117; the two figures were recorded as given
  and not reconciled.
- Every other default on the pages checked on Windows (Layout, Display, Color, Folder Tabs, View Mode, Operation,
  Edit/View, Copy/Delete, Quick Search, Thumbnails, Misc) was the same in both sessions.

_Basis: observed under Wine and on Windows 11; help: inisettings2 (`UseNewDefFont`), inisettings3 (`Fontname`,
`Fontsize`, resolution sections)._

### 2.3 How TC stores DPI-dependent values

- Geometry, fonts, icon sizes, cursor width, thumbnail zoom, column tabstops and tool-window positions live in the
  **screen-resolution section** (19 › INI rules › Screen-resolution sections). `ResolutionSpecific=0` puts them into
  `[AllResolutions]`, which is also the fallback when no section for the current resolution exists.
- Some keys carry the DPI in their name: `<Key><dpi>` and `<Key>_<dpi>` hold the value for that DPI, `<Key>_dpi` the DPI
  at which a value was saved (examples: `Buttonheight96=`, `Iconsize32_120=`, `ExtraDriveWidth_dpi=`).
- Per monitor, the main monitor's section holds `monitor(x,y,dx,dy;dpi)=x,y,dx,dy`.
- `[Tabstops]` is used only when no tabstops are stored for the current resolution.

Rules for a clone:

1. Derive the default fonts, icon size, tabstops and row height from the system DPI and font metrics; do not hard-code
   the 96-DPI values.
2. Store and look up these values per screen resolution as above.
3. Scale the dialogs with the system DPI (_Set dots per inch_ is off by default; _Automatically adjust dialog boxes to
   larger fonts_ is on).

_Basis: help: inisettings, inisettings3; HISTORY.TXT (`[AllResolutions]` fallback, per-monitor positions); observed
under Wine and on Windows 11._

modifier-only key events were withheld. All Alt shortcuts in this specification therefore come from `KEYBOARD.TXT`, the
help and the shortcut texts in `WCMD_ENG.MNU`; on Windows (Parallels forwards Option as Alt) a subset was pressed and
confirmed.
